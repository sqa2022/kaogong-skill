# 申论分支范围说明

分支名：`feat/shenlun-core`

## 当前目标

只解决三件事：

1. 题目分析讲解并写作
2. 查找并给出参考范文
3. 批改打分用户提交的申论

## 当前命令设计

对外只保留一个显式入口：`/shenlun`。

通过 mode 参数区分：
- `analyze`
- `exemplar`
- `grade`

## 暂不纳入

- 行测题库与解析
- 招考公告抓取
- 职位匹配
- 实时网页检索依赖的复杂工作流
- 省份差异化的精细官方评分映射

## 设计取舍

### 1. 为什么先用一个总入口？
因为更利于演示、传播和冷启动，也更便于在一个 skill 内统一维护审题、范文和批改的共享规则。

### 2. 为什么先不用 fork subagent？
因为第一版重点兼容用户直接把材料或草稿贴进对话的场景。若技能设成 `context: fork`，它不继承当前对话历史，更适合明确的文件型任务，不利于“我把稿子贴给你直接改”这种交互。

### 3. 为什么先用内部练习分？
因为官方阅卷口径、题型、地区差异较大。第一版先把内部打分的一致性做出来，再做 profile 化映射。

## 成功标准

- `/shenlun analyze` 能稳定输出题目拆解、立意、提纲和可写作版本。
- `/shenlun exemplar` 能优先检索本地样例，并在缺少样例时产出清楚标注的 AI 参考范文。
- `/shenlun grade` 能稳定给出分项评分、主要失分点、重点改写和训练建议。

## v0.1 交付物

- 一个主 skill：`shenlun`
- 三类模式：analyze / exemplar / grade
- 至少三篇内置 AI 合成样本范文
- 一个最小 HTML 报告脚本
- 两个合成示例文件：示例题、示例作答
- 一个最小评测清单
